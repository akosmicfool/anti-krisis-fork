FAIL (DexScreener down/rate-limited): canBurn=false → Burn button disabled. Msg: "Price unavailable — network error." Action: none needed — wait. No burn submitted, nothing to recover.

settled+success: → claim-first submission (below).
settled+reverted: terminal "Burn Failed — the transaction failed on-chain." No fee. Correct: no claim is created for a reverted burn.
NOT settled in 90s: claim submitted with feeTxHash="" → Burn History owns it. Modal: "verification taking longer… Burn History will show Fee Pending with Pay Fee."
GAP-2: frontend TX_INDEX_RPCS ≠ backend rpcUrlForChain — OP has ONE frontend endpoint (mainnet.optimism.io, no fallback), ETH list still leads with publicnode+ankr+cloudflare (the endpoints that blocked the canister; ankr is key-gated → result:null treated as "not indexed"). FE claim-first
OK: initiateClaim(feeTxHash="") → claim lands in Burn History as #pending immediately (slow path and settled path both — every burn is recoverable).
FAIL (canister unreachable / Candid reject): slow-path: swallowed (Re-check Tx picks it up). Fast-path claim submission failure → error handler: if fee never sent and claim exists → pending_fee amber "burn saved in Burn History — use Pay Fee"; if no claim → failed(failStep 1).
Backend rejects (LAUNCH_NOT_STARTED / NFT_GATE_BLOCKED / duplicate): mapped to plain-language messages, terminal failed. Duplicate of a FAILED claim by the same user → resurrect path (fresh fee allowed); by another user → adoption rule (W4/F4).
BE burn verify
Backend: canonical hash → duplicate/adoption guard → burn receipt RPC (verifyFeeTxWithReceipt path: endpoint 1→2→3, junk guard skips 403/429 bodies; result:null = not-indexed = PENDING).
verified: Transfer-to-dead/AAM parsed → amountBurned+usd committed ATOMICALLY with status. (fixed 2026-09-11: the timer path now also commits when fee-less — GAP that emptied amountBurned is closed.)
price fail here: claim stays #pending, 15s timer retries price (fail-closed; AKK-3). Frontend: 20s reassurance note then 35min hard timeout.
TX_FAILED (burn reverted): → #failed, "Burn Failed" badge + Retry Claim.
RPC all-dead: PENDING loop until endpoints recover (self-healing timer). This was the v338 incident class — now guarded by junk-shape filter + probed endpoint sets.
PHASE B — fee submitted → GRITmodal steps 2–3
FE fee size
getPlatformFeeInfo: feeUsd = burnUsd × 0.69% ÷ CoinGecko native price. sendPlatformFee recomputes at send time.
FAIL (CoinGecko down): throws "Native price fetch failed" → if claim already submitted → pending_fee amber "burn saved in Burn History — Pay Fee" (recoverable). No fee lost (none sent).
GAP-3 (pricing-source split): frontend sizes the fee in ETH via CoinGecko; backend checks the amount against DexScreener-priced usdValue ÷ backend native price (DexScreener WETH). Two independent price sources for the SAME check — 7% tolerance absorbs drift, but during volatility/oracle disagreement honest fees can fail with MINER_FEE_UNDERPAID (claims) / BINDING_FAIL underpaid (burn claims). Action: consider same source both sides, or widen tolerance.
WAL fee tx
OK: sendPlatformFee → calldata = binding(principal, burnHash) → value=feeWei → FeeCollector (relay wallets: tx.to=forwarder, FeePaid event carries it — backend event path handles).
User rejection: step=pending_fee (Step1 ✓ "Burn transaction confirmed", Step2 "Fee cancelled — nothing was charged"), Burn History: Fee Pending badge + Pay Fee button (fixed v339). Backend claim remains #pending fee-less; timer commits burn amount (fix #1).
Nonce race / wallet drop ("hash returned but tx never landed"): feeStillPending guard → stays awaiting_fee_confirm with price-note; if truly never lands → 15s backend timer sees no fee... claim #pending fee-less → Pay Fee recovers. Wallet-side fix: fresh attempt (known wallet staleness class).
Fee send throws BEFORE popup (config/price): same pending_fee amber path.
BE fee verify
retryFeeClaim (frontend-triggered) or recheckFeeClaim (15s timer): store fee hash FIRST (Bug-1), then receipt → FeePaid event (value+binding) → payer==tx.from → recipient (relay-tolerant) → payload binding == (claimant, burnHash) → AKK-10 amount floor (paid ≥ 0.69% × usd × (1−7%)).
all pass → credit: calcGrit(amountBurned × price × 1T/$1) → balances += grit, status #verified — atomic.
PENDING / unparseable: stays #pendingFee, retried every 15s. Modal escalates to pending_fee after grace (5min L2 / 90s L1 per older notes) but KEEPS polling (09-03 lesson).
TX_FAILED (fee reverted): fee hash cleared → Pay Fee (new payment).
structural binding mismatch: #failed → Retry Claim.
amt==0 (fee paid before burn verified — the v338 OP/ETH incident): now re-verifies burn first, commits amount, THEN fee-checks and credits from the recovered amount (fixed twice — 6fc7a96 then 5a25ba4 stale-credit catch).
kVCM relayer path: burn sender == fee sender normally; for relayed burns verifyFeeBinding LAZILY fetches the burn receipt and parses the Transfer-log burnOwner when senders mismatch (Bug-2, grit-api.mo L302–309) — burnOwner=null in the fee paths is therefore safe (one extra outcall, not a hole). kVCM stuck-claims were the timer death, not this.
BE timer
recheckPendingClaims: every 15s, self-healing re-arm (trap can no longer kill it — 2026-09-12 fix), body try/catch (rejects logged), adaptive eligibility for #pending by age, ALL #pendingFee every tick.
GAP-5 (known, accepted): re-arm-first allows overlapping fires when body >15s → duplicate outcalls, no double-credit (CAS).
