Plain English: you burn a token → the app asks the canister to track it → you pay a small fee on-chain → the canister re-reads the chain to prove both, then mints GRIT. A separate "create miner" action spends GRIT and charges its own fee. Everything the canister believes, it re-proves from public RPC data — there is no trust in the frontend.

3 · Claim state machine (backend truth)

#pending
amountBurned=0 until burn verifies→ #pendingFee
fee hash stored (Pay Fee / retryFeeClaim)→ #verified
CAS-guarded credit, idempotent
  • #failed reachable from both; only the original claimant can resurrect it with a (new) fee hash.
  • W4/F2 guard (grit.mo:157-160): a #verified transition with 0 GRIT and 0 amount is refused — claims can't be terminalized at zero.
  • W1A CAS guard (grit.mo:113-201): credit happens once, to updated.claimant at write time.
  • No expiry anywhere: every stuck state stays recoverable by design.
  • Adoption (W4/F4, grit.mo:226-243): a different caller may adopt any uncredited claim — anti-squatting relief. This is where the critical race lives (F-C1).

7 · Ranked findings (merged: 5 subagent audits × my ground-truth pass, deduped, evidence-verified)

#SevFindingPlain EnglishTechnical (evidence)Fix
1CRITAdoption race steals an in-flight credit A stranger watching the chain can adopt your pending claim during the seconds the robot is verifying your fee — the GRIT lands in their account while you paid burn + fee. grit.mo:226-243 rebinds claimant on any uncredited claim; credit pays updated.claimant at CAS-write time (grit.mo:175-196); adoption is synchronous at grit-api.mo:439-453 while the victim's retryFeeClaim/recheckFeeClaim sits inside its verifyFeeBinding awaits; CAS only re-checks status, not claimant. Carry the proof-passing principal into updateClaimStatus and credit only if it still equals the stored claimant; forbid adopting claims carrying a fee hash.
2CRITAKK-10 fee floor skipped when the burn verifies via the timer (combined claim path) There's a back door where the "did you pay enough fee?" check silently skips — a crafted direct call mints full GRIT while paying ~zero fee. (Confirmed independently by two auditors.) Claim stored with fee hash + usdValue 0 (grit-api.mo:472-488); timer passes stale record.usdValue=0.0 (:853); check gated on usd > 0.0 (:344-346, fee-amount.mo:149-161); full credit from the real receipt amount (:881-884). Frontend never sends this shape; the canister endpoint is public. Pass ?usdValueRecheckBurn (computed :811) — commit amount+usd before the fee check; treat usd ≤ 0 as PENDING, not "no check".
3CRITRecovery-path fees sized from token count, not USD (~1/token-price error) When you pay a fee from Burn History or Recent Burns, the app multiplies your token amount by 0.69% instead of the dollar value — a 1000 kVCM burn charges ~71× the intended fee; expensive tokens underpay and get failed with the fee sunk. BurnHistoryPage.tsx:331, :412 and BurnPage.tsx:1907 pass Number(claim.amountBurned) into sendPlatformFee, which computes feeUsd × feeRate (use-wallet.ts:365-371); the correct inline path passes burnValueUsd (BurnPage.tsx:841-861). Found by 3 independent auditors; verified. Pass Number(claim.usdValue); rename the param to burnValueUsd.
4CRITMiner-fee replay key fails open + unvalidated hash into JSON-RPC body The "this fee was already used" check can silently stop working for a crafted hash string, so one real fee could mint unlimited miners. (Needs a live probe to confirm the JSON-injection precondition; the fail-open key alone is real.) mining-api.mo never canonicalizes feeTxHash (no ClaimIdentity import — verified); raw hash interpolated into the RPC body (verification.mo:39-47, :54-61); isMinerFeeConsumed/consumeMinerFee no-op on canonicalization error (mining.mo:606-618) while the claim path canonicalizes first (grit-api.mo:395). Validate + canonicalize feeTxHash (32-byte hex) before ANY RPC; fail closed in minerFeeKey consumers.
5HIGHDisarming FeePaid silently disables the fee-amount floor If an admin ever uses the emergency disarm switch, the "did you pay enough?" check vanishes entirely — any dust payment buys full GRIT. (The miner path refuses instead — the claim path doesn't.) paidValueWei only set inside if (fee.requireFeePaidEvent) (grit-api.mo:245-260); floor block requires ?paid (:344); miner path guards (mining-api.mo:127-129). Enforce the floor from tx-level value when disarmed, or refuse fee-bearing claims while disarmed (mirror the miner path).
6HIGHFree unauthenticated claim spam + public sweep → permanent cycle drain Anyone on the internet can create unlimited fake claim records and force full verification sweeps forever — the robot does expensive chain lookups for nothing, forever, by design (no expiry). Record stored before any proof (grit-api.mo:472-488); shape-only validation (claim-identity.mo:29-67); recheckPendingClaims public (:1049); no expiry (grit.mo:365-372); serial per-claim awaits, no batch cap (:1074-1082). Found by 3 auditors. Require the receipt to exist before storing; cap per-sweep batch; per-caller pending limit; rate-limit the sweep.
7HIGHFee-stage failure is a dead end — no way to pay a NEW fee If your fee fails for a structural reason (underpaid, wrong recipient), the only button re-runs the same failed payment proof. Your escape is a brand-new burn — real tokens destroyed twice. #failed maps only to Retry Claim (claim-recovery.ts:42-60); handleRetryClaim re-sends claim.feeTxHash ?? "" — the old doomed hash (BurnHistoryPage.tsx:376-380, verified); retryFeeClaim refuses non-pending claims (grit-api.mo:1128-1143). Backend resurrection WOULD accept a fresh hash (grit.mo:83-93) — the UI never offers one. Offer Pay Fee for #failed claims with amountBurned > 0; resurrect with feeTxHash: "".
8HIGHFrontend price picker lacks the backend's dust-pair/base-token filter The fee you're shown (and the sanity check) can be computed from a garbage price quote — the exact bug class that once priced kVCM 11× too high was fixed in the canister but not in the webpage. utils/dexscreener.ts:21-49 — highest-liquidity pair with any priceUsd; baseToken.address and chainId never checked; backend fixed this class (price-oracle.mo:70-82,139). Port the base-token + chainId filter (or consume the backend oracle).
9HIGHAdoption wipes paid-fee evidence → repeatable fee griefing The same adoption mechanic (fixing one attack) enables another: a griefer can repeatedly erase the record of your paid fee, forcing you to pay again each time. Adoption sets feeTxHash := null on claims that may carry a paid hash (grit.mo:235-239); the erased hash can never be re-verified (claimant-locked grit-api.mo:1119-1121). Restrict adoption to fee-less / #failed claims.
10HIGHTimer credits at current price while the floor used claim-time price The reward and the fee check can be priced at different moments — honest users can be failed after a price drop (fee sunk), and deliberate timing can tilt the ratio. Credit: current price (grit-api.mo:807,883, :1027-1039); floor: stored claim-time usd (:853, :978); user-driven retry: current (:1186). One comparator policy: floor at fee-payment-time price, credit at credit-time price, stored explicitly.

8 · What holds (verified sound — don't re-litigate)

  • Double-credit protection: CAS guard re-reads authoritative status immediately before mutation, no await between (grit.mo:113-201) — repeated/concurrent verification is idempotent.
  • Zero-credit terminalization: W4/F2 refusal (grit.mo:157-160).
  • Claim-first ordering: the burn is always in Burn History before any fee is charged (BurnPage.tsx:821-837).
  • Canonical identity: one tx = one claim across all spellings; validate-before-outcall (claim-identity.mo).
  • Fee↔miner payload separation: 1+len+32 vs 1+len+4, mutually exclusive decoders (verification.mo:291-318 vs :930-972) — a claim fee can never pay for a miner and vice versa.
  • D1 armed-anywhere: omitting/misspelling feeChain can't skip the miner gate (mining-api.mo:95-131, mining.mo:550-591).
  • Miner-fee single use: all awaits before one await-free tail (replay check → debit → insert → consume-on-success) (mining-api.mo:212-233).
  • Self-healing claim timer: fire-once re-arm-first + try/catch (main.mo:723-736) — one bad response can't kill it.
  • AKK-10 decode: FeePaid value from ABI head word 1, validated against live receipts (fee-amount.mo:74-124); zero-payment failure (F1 fix) when armed and priced.
  • Transient-vs-structural discipline: RPC artifacts keep claims pending; only structural mismatches fail (grit-api.mo:698-717, :863-880, :990-1013).
  • Non-JSON RPC junk rejection on both fee/receipt fetch paths (verification.mo:775, grit-api.mo:95-96).
  • No-expiry recovery model: every stuck claim stays user-recoverable; failed claims resurrectable by the original claimant only.
